> Hermes Agent를 VPS에 올린 뒤, 폰과 노트북 어디서든 명령을 보낼 창구를 만들려는 사용자

# 이 가이드에 대하여

Telegram은 Hermes에 붙이는 가장 빠른 메신저 창구입니다. 토큰 하나와 숫자 ID 하나면 끝납니다. Slack처럼 권한 스코프를 고르거나 앱을 설치할 필요가 없습니다.

메신저 게이트웨이는 Hermes 서버와 별개 프로세스로 VPS에서 실행됩니다. 노트북 Hermes Desktop을 종료해도 Telegram 응답은 유지됩니다. Desktop은 설정 화면 역할만 합니다.

# 준비물

- Telegram 계정 (폰 또는 데스크탑)
- VPS에서 실행 중인 Hermes Agent
- 노트북의 Hermes Desktop (Remote Gateway 연결 상태)
- 비밀번호 관리자

# 명령 실행 위치 표기

- **[노트북]** 내 컴퓨터의 Hermes Desktop
- **[Telegram]** Telegram 앱 화면
- **[Hermes]** VPS 컨테이너 터미널

# 전체 흐름

```text
BotFather에서 토큰 발급
        ↓
userinfobot에서 숫자 ID 확인
        ↓
Hermes Messaging에 두 값 입력
        ↓
게이트웨이 재시작
        ↓
봇에게 DM → 응답 확인
```

## STEP 1. Bot Token을 받습니다

### 목표

Telegram에서 봇을 만들고 토큰을 확보합니다.

봇은 Hermes에 명령을 전달하는 창구입니다. Telegram 안에서 만들며 별도 프로그램을 설치하지 않습니다.

### 실행

**[Telegram]** 검색창에 `BotFather`를 입력하고, 파란 체크 표시가 붙은 **@BotFather**를 엽니다. 이름이 비슷한 가짜 계정이 있으므로 체크 표시를 확인합니다.

1. 하단 **시작(START)** 버튼을 누릅니다.
2. 입력창에 `/newbot`을 보냅니다.
3. **봇 이름**을 입력합니다. 대화 목록에 표시될 이름이며 한글도 됩니다.

```text
Hong-hermes
```

4. **사용자 이름**을 입력합니다. 규칙은 세 가지입니다.

- 영문 소문자·숫자·밑줄만 사용
- `bot`으로 끝날 것
- 5자 이상

```text
hongss_hermes_bot
```

`Sorry, this username is already taken`이 나오면 다른 이름을 넣습니다. 이미 쓰는 사람이 있다는 뜻입니다. 앞에 본인 식별자나 용도를 붙이면 대개 통과합니다.

```text
hongss_hermes_vps_bot
```

성공하면 아래 형태로 답이 옵니다.

```text
Done! Congratulations on your new bot. You will find it at
t.me/hongss_hermes_vps_bot
...
Use this token to access the HTTP API:
1234567890:AAFxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### 토큰 다루기

`숫자:영문자` 한 줄 전체가 토큰입니다. 콜론 앞 숫자만 복사하는 것이 가장 흔한 실수입니다.

파란 글씨의 토큰 줄을 **클릭하면 자동 복사**됩니다. 드래그하면 앞뒤 공백이나 줄바꿈이 딸려옵니다.

비밀번호 관리자에만 보관하고 캡처·문서·채팅에 원문을 남기지 않습니다.

> 이미 만든 봇이 있거나 봇을 여러 개 운영한다면 부록 C를 먼저 봅니다. 토큰을 잘못 재사용하면 메시지가 두 서버로 갈립니다.

### 결과 확인

- [ ] BotFather에서 봇을 만들었습니다.
- [ ] `숫자:영문자` 형태의 토큰 전체를 확보했습니다.
- [ ] 비밀번호 관리자에 저장했습니다.

## STEP 2. 본인 Telegram 숫자 ID를 확인합니다

### 목표

허용 목록에 넣을 숫자 ID를 확보합니다.

이 값을 비워 두면 봇 사용자 이름을 아는 사람은 누구든 Hermes에 명령을 보낼 수 있습니다. 선택 항목이 아닙니다.

### 실행

**[Telegram]** BotFather 대화창이 아닙니다. 별도 대화방으로 들어갑니다.

1. 대화 목록 위쪽 **검색창**을 클릭합니다.
2. `userinfobot`을 입력합니다.
3. 검색 결과에서 **@userinfobot**을 선택합니다.
4. 하단 **시작(START)** 버튼을 누릅니다. 버튼이 없으면 `/start`를 보냅니다.
5. `hi` 정도로 한 줄 보냅니다.

봇이 이렇게 답합니다.

```text
Id: 123456789
First: 성흥
Lang: ko
```

`Id:` 뒤의 숫자만 복사합니다. 보통 9~10자리입니다.

### 값 구분

| 값 | 형태 | 용도 |
|---|---|---|
| 숫자 ID | `123456789` | 허용 목록에 넣을 값 |
| 사용자 이름 | `@hong` | 사용하지 않음 |
| 전화번호 | 010-… | 사용하지 않음 |

계정마다 고정된 값이며, 폰에서 확인해도 같은 숫자가 나옵니다.

### 결과 확인

- [ ] `Id:` 뒤 숫자를 확보했습니다.
- [ ] 사용자 이름이 아니라 숫자입니다.

---

## STEP 3. Hermes Desktop에 입력합니다

### 목표

토큰과 숫자 ID를 등록합니다.

### 실행

**[노트북]** Hermes Desktop 좌측 메뉴에서 **Messaging**을 열고 **Telegram**을 고릅니다.

1. **Bot token** 칸에 토큰을 붙여넣습니다.
   - 콜론 앞뒤에 공백이 없어야 합니다.
   - 앞뒤 따옴표·줄바꿈이 딸려오지 않았는지 확인합니다.
2. **Allowed Telegram user IDs** 칸에 숫자 ID를 넣습니다.

여러 명을 허용하려면 공백 없이 쉼표로 잇습니다.

```text
123456789,987654321
```

3. 입력칸 밖을 클릭해 포커스를 뺍니다.

각 항목 옆에 `Saved`가 뜨면 저장된 것입니다. **별도 저장 버튼은 없습니다.** Slack 화면과 다른 점입니다.

### 배지 판정

| 배지 | 의미 |
|---|---|
| `Needs setup` 사라짐 | 토큰 형식이 통과했습니다 |
| `Disabled` 사라짐 | 커넥터가 켜졌습니다 |
| `Restart needed` 등장 | 정상입니다. 다음 단계에서 재시작합니다 |

`Needs setup`이 남아 있으면 토큰 칸을 비우고 다시 붙여넣습니다. 공백이나 줄바꿈이 섞인 경우가 대부분입니다.

### 우측 미리보기 오류

화면 오른쪽에 `Preview unavailable` 또는 `404: File not found`가 떠도 연결과 무관합니다. 미리보기 패널의 문제이므로 그대로 진행합니다.

### 결과 확인

- [ ] Bot token과 Allowed Telegram user IDs 두 칸이 모두 `Saved`입니다.
- [ ] `Disabled`와 `Needs setup` 배지가 사라졌습니다.

---

## STEP 4. 게이트웨이를 재시작합니다

### 목표

저장한 설정을 실제로 적용합니다.

**재시작 전에는 값을 저장해도 봇이 반응하지 않습니다.** 이 단계를 건너뛰어 막히는 경우가 가장 많습니다.

### 실행

**[노트북]**

1. Hermes Desktop **하단 상태 표시줄**을 봅니다.
2. 게이트웨이 상태 표시(초록·회색 점 또는 `Gateway` 표기)를 클릭합니다.
3. 메뉴에서 **Restart**를 고릅니다.
4. `Restart needed` 주황 배지가 사라지면 완료입니다.

화면 안내문도 같은 말을 합니다. "Restart the gateway from the status bar to apply this change."

### 결과 확인

- [ ] 게이트웨이를 재시작했습니다.
- [ ] `Restart needed` 배지가 사라졌습니다.

---

## STEP 5. Telegram에서 시험합니다

### 목표

응답과 명령 작동을 확인합니다.

### 실행

**[Telegram]**

1. 검색창에 만든 봇의 사용자 이름을 입력합니다.
2. 봇을 열고 **시작(START)**을 누릅니다.
3. 메시지를 보냅니다.

```text
현재 사용 중인 모델 이름과 연결 상태만 알려줘.
```

응답이 오면 토큰과 허용 목록이 모두 정상입니다.

이어서 명령을 시험합니다.

```text
/status
/model
/help
```

마지막으로 이 대화창을 결과 수신 홈 채널로 지정합니다. 크론잡 결과가 이 방으로 옵니다.

```text
/sethome
```

### 응답이 없을 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 무응답 | 게이트웨이 미재시작 | `Restart needed` 배지 확인 |
| 무응답 | 숫자 ID 불일치 | @userinfobot 값과 대조, 오타 확인 |
| 무응답 | 토큰 손상 | 콜론 앞뒤 공백·줄바꿈 확인 후 재입력 |
| 응답이 끊김 | 토큰 중복 사용 | 같은 토큰을 쓰는 다른 서버의 게이트웨이 중지 |
| 봇을 못 찾음 | 사용자 이름 오타 | BotFather의 `t.me/...` 주소로 접속 |

### 결과 확인

- [ ] 허용된 본인 계정에서 응답을 받았습니다.
- [ ] `/status`, `/model`, `/help`가 작동합니다.
- [ ] `/sethome`으로 홈 채널을 지정했습니다.

---

## STEP 6. 토큰을 관리합니다

### 목표

노출된 토큰을 교체하고, 이후 보관 규칙을 정합니다.

### 언제 교체하는가

- 캡처·문서·채팅에 토큰 원문이 남았을 때
- 화면 공유나 강의 시연에 토큰이 노출되었을 때
- 봇을 다른 담당자에게 넘길 때

토큰을 아는 사람은 누구든 봇을 조종할 수 있습니다. 노출을 확인하면 미루지 않습니다.

### 실행

**[Telegram]** `@BotFather`에서:

```text
/revoke
```

봇을 고르면 새 토큰이 발급되고 **이전 토큰은 즉시 무효화**됩니다.

**[노트북]** Hermes의 **Bot token** 값을 새 토큰으로 바꾸고, STEP 4의 게이트웨이 재시작을 다시 실행합니다.

### 결과 확인

- [ ] 노출된 토큰을 교체했습니다.
- [ ] Hermes에 새 토큰을 넣고 재시작했습니다.
- [ ] 새 토큰을 비밀번호 관리자에만 보관했습니다.

## 부록 A. Messaging 메뉴가 없을 때

Hermes 버전에 따라 Desktop에 Messaging 메뉴가 없을 수 있습니다. **[Hermes]** 컨테이너 터미널에서 같은 설정을 합니다.

```bash
hermes gateway setup
```

플랫폼 목록에서 Telegram을 고르고 Bot Token을 입력합니다. 허용 사용자는 환경변수로 지정하며, 게이트웨이는 목록에 없는 사용자를 모두 차단합니다.

```text
TELEGRAM_ALLOWED_USERS=123456789
```

## 부록 B. 대화 목록이 가입 알림으로 채워질 때

Telegram을 처음 쓰면 "○○님이 텔레그램에 가입했습니다" 알림방이 수십 개 생깁니다. 연락처에 저장된 번호가 가입할 때마다 자동으로 만들어지는 방입니다. Hermes 봇이 이 사이에 묻힙니다.

순서를 지켜야 헛수고가 없습니다. 방을 먼저 지우면 계속 다시 생깁니다.

### 1. 알림부터 끕니다

**[Telegram]** 설정 → **알림 및 소리** → **연락처 가입 알림** 체크 해제. 데스크탑에서 됩니다.

### 2. 동기화된 연락처를 지웁니다 (선택)

폰 앱에서만 됩니다. 설정 → **개인정보 및 보안** → **연락처 동기화** 끄기 → **동기화된 연락처 삭제**.

되돌릴 수 없고 실제 지인의 연결도 끊어집니다. 판단해서 건너뛰어도 됩니다.

### 3. 남은 방을 정리합니다

폰에서 대화방을 **길게 눌러** 선택 모드로 들어가면 여러 개를 한 번에 삭제·보관할 수 있습니다. 데스크탑에는 이 다중 선택이 없어 하나씩 우클릭해야 합니다.

지우지 않고 폴더로 걸러도 됩니다. Hermes 봇만 담은 폴더를 만들면 목록은 그대로 두고 화면만 정리됩니다.

## 부록 C. 봇을 여러 개 운영할 때

### 하나의 토큰은 한 서버에만 붙입니다

같은 Bot Token을 두 서버가 동시에 폴링하면 Telegram이 409 Conflict를 반환하고, 메시지가 두 서버로 무작위로 갈립니다. 한쪽에서는 답이 오고 다른 쪽에서는 안 오는 증상으로 나타납니다.

새 장비에 Hermes를 올릴 때는 **봇을 새로 만듭니다.**

### 기존 봇을 새 서버로 옮길 때

토큰을 재사용하려면 순서를 지킵니다.

1. 이전 서버의 게이트웨이를 중지합니다.
2. `@BotFather`에서 `/mybots` → 봇 선택 → **API Token**으로 토큰을 다시 받습니다.
3. 새 서버의 Hermes에 입력하고 재시작합니다.

### 표시 이름으로 구분합니다

봇이 여러 개면 대화 목록에서 구분이 안 됩니다. 어느 장비용인지 이름에 넣습니다.

`/mybots` → 봇 선택 → **Edit Bot** → **Edit Name**

```text
Hong-hermes VPS
```
